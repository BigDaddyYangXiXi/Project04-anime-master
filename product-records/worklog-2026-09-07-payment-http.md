# P06b：原始支付通知 HTTP 适配 — 2026-09-07

payment-api 更新为 `0.6.0`，客户端仍为 `.12`，数据库仍为 19 个迁移。本批实现 CloudBase 普通云函数的 HTTP 集成响应适配，并增加本机真实 HTTP 收发到数据库、订单及双方页面方法的测试。没有注册或部署公网入口，没有把本机 HTTP 桥接器当作云平台网关验收。

## 接收与应答规则

依据 [CloudBase HTTP 访问普通云函数](https://docs.cloudbase.net/service/access-cloud-function) 与 [集成响应格式](https://docs.cloudbase.net/cloud-function/how-coding)：接收 httpMethod、headers、字符串 body 和可选布尔 isBase64Encoded，返回 statusCode、headers、字符串 body。沿用本项目普通云函数模式，不引入另一种 HTTP 框架。

- 仅 POST。字符串主体保留 UTF-8 字节；Base64 主体须规范编码、明确解码一次。不把 JSON 对象重新序列化为“原文”，不自动解压或 URL 解码。
- 主体最大 2 MiB，解码前后均检查。拒绝不支持的压缩、歧义头结构、错误编码标记；重复签名头继续由验签器拒绝。
- 支付记录、订单和事件事务确认提交后返回真实 HTTP 204、空主体；需人工核对但已可靠保存的到账也按已接收应答。
- 格式错误 400、签名／解密错误 403、超大主体 413、配置或公钥缺失 503、数据库或其他内部错误 500；方法不符 405。所有失败主体都是通用 FAIL 消息，禁止返回 HTTP 200 包裹一段错误 JSON。
- 日志仅记录固定范围及白名单错误码。不记录原报文、签名头、SQL、付款人、交易号或原始异常；日志自身失败仍保留失败应答。

## 对应到服务与页面

| HTTP 结果 | 数据库与业务结果 | 页面结果 |
| --- | --- | --- |
| 正常／待核对到账已提交后 204 | 沿用已有到账事务和幂等规则 | 双方读取同一 PAID／PAYMENT_REVIEW，资金列表引用同笔支付事实 |
| 验签或格式失败 | 未进入到账事务 | 不出现假付款、执行或资金记录 |
| 数据库失败 500 | 未完成的事务回滚 | 仍读取原订单事实，不提前放行 |
| 已提交但提交回执丢失，首次 500 | 数据库已保留事实；下一次可信通知幂等读取后 204 | 不因重试新增一笔收入、订单版本或事件 |

复用现有 `.12` 的付款已确认、付款待核对及继续付款画面，无新增业务状态或重复按钮。公开客户端仍只读业务订单，尚未接入主动渠道查询。
