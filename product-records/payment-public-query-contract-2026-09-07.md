# 公开付款结果查询：前后端实施契约

2026-09-07，只读梳理现有代码后的下一阶段实施约束。本文件是开发契约，接口尚未实现或开放；不表示已接入真实微信查单。

## 当前可复用能力和缺口

- payment-api/wechat-query.js 的 queryPayment 已能对数据库中存在的支付单请求微信并验签入账，但它是内部方法，不能直接把客户端传来的 paymentId 接进去。
- payment-api 当前没有公开 index.js，也未在云函数配置中注册。原生 SQL 事务连接与商户密钥仍缺少生产装配；order-api 当前采用 CloudBase RDB 读取，不能把两种连接未经验证地当作同一事务。
- booking-status 在收银台返回和下拉刷新时只调用 cloudOrders.getOrder。getOrder 是业务订单只读接口，不能在其中隐式调用付费渠道查询，使普通页面打开变成不可控的渠道轮询。
- order-detail 与 provider-request 读取同一业务订单状态；.14 已保护三页的旧响应覆盖。它们无需增加第二套付款状态或独立轮询器。

## 单条完整链路

1. 需求方在收银台返回后，或在付款确认中主动下拉刷新，进入明确的 refreshPayment 动作。每次页面只保留一个该动作在途，不创建定时轮询。
2. 服务端用可信微信上下文解析有效账号和 BUYER 角色，核对 order_aggregates.buyer_id。仅接受 orderId，不接收账号、OpenID、商户号、金额、付款状态或渠道地址作为判断依据。他人订单统一返回不可读取，不请求渠道。
3. 服务端从该订单持久化支付记录选择需要查询的活动记录。没有支付记录时返回未开始查询，不声称微信确认未支付；已到账或待核对记录只读取已有事实，不重复查单或自动解除待核对。
4. 通过数据库持久化的查询时间／租约控制跨实例重复调用。锁内领取、提交后请求网络，不能跨微信请求持有订单数据库锁。失败也计入冷却，租约有到期恢复，旧查询完成不能释放新租约。实现时将具体间隔作为运维常量并测试，不伪称微信官方限额。
5. 沿现有 queryPayment 的固定域名、签名、响应验签和到账事务处理渠道结果。请求失败、验签失败和频率限制都不能写成未付款、关闭或到账。
6. 查询结束后使用同一订单权限规则重新读取业务订单快照。页面沿现有 renderOrder 展示 PAID／PAYMENT_REVIEW／VERIFYING／仍未确认，保留 .14 版本保护；失败保留上次事实并允许稍后重试。付款资格继续以服务端最新条件为准。

## 页面、接口、数据、反馈对应

| 场景 | 服务端／数据库规则 | 页面反馈 |
| --- | --- | --- |
| 无可信身份／非本人订单 | 拒绝，不领取租约、不请求微信、不变更支付 | 登录要求或订单不可读取，不能暴露他人付款情况 |
| 该订单还没有支付记录 | 只读业务事实，不创建支付单 | 尚未发起付款；沿已有付款门禁 |
| 查询已在途或仍在冷却 | 只读当前订单并返回明确的稍后重试状态 | 保留当前结果，停止本次刷新，不增加循环请求 |
| 有效签名 SUCCESS | 复用既有到账事务、幂等和付款人核对规则 | 已确认或待核对；双方后续读取同一状态 |
| 有效签名 NOTPAY／PAYERROR | 仅确认渠道当前返回，不凭空制造到账 | 仍未确认付款；是否可再次付款由业务资格决定 |
| 有效签名 CLOSED | 仅关闭匹配的支付记录，复用旧单／新单保护 | 服务端确认恢复资格后才允许继续付款 |
| 超时／无配置／错误签名／云额度耗尽 | 不修改支付事实，安全结束本次查询租约 | 核对暂不可用，不把现有 PAID／PAYMENT_REVIEW 清空 |

## 实施顺序与验收条件

1. 写出失败回归：伪造身份／他人订单不请求渠道；同订单多实例仅一个外呼；失败冷却、超时租约恢复、旧租约完成不得释放新租约。
2. 最小数据库迁移与服务端查询入口，在本机真实 MySQL 验证锁、事务与权限。生产连接未具备时保留明确配置错误，不装配虚假连接或演示记录。
3. cloudOrders.refreshPayment 与 booking-status 收银台返回／下拉刷新一次性接入，并验证原页面的加载、错误、再次操作、返回和卸载；order-detail／provider-request 继续复用业务订单快照。
4. 使用既有签名渠道夹具完成请求—验签—MySQL—业务权限读取—客户端映射—双方页面方法的端到端测试；再取得对应原生页面状态证据。完整批次通过后才可称本地链路完成。

真实云调用、手机号授权和既有账号登录仍受云资源额度阻塞；不反复调用生产环境。公网装配、真实商户查单与真机支付必须另行验证。费率、F07 档期容量、真实关单、退款、验收分账均不在本批中默认为已实现。
