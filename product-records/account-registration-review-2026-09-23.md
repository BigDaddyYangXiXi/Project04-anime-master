# 注册、昵称与账号规范修订稿

状态：用户提出七项问题后的方案与协议初稿，未生效。旧开发预览不能作为正式注册验收通过证据。

## 当前事实

- 昵称注册与资料编辑上限为20，但计数实现存在差异：注册使用 graphemes，资料页使用字符串 length；服务端还需统一。尚未完成全昵称场景的完整画面测量，不直接缩短上限。
- account-bootstrap 注册、account-api 改名目前没有文本内容审核调用。现有图片审核不能代替昵称审核。
- “微信一键注册”实际使用 getRealtimePhoneNumber；“使用微信身份注册”只用可信微信身份。项目无自建短信验证码发送服务。用户看到的验证码具体来源尚需其界面证据确认。
- 原账号使用说明仅三句弹窗，既不是完整用户协议，也不是完整隐私政策。
- 注册提交中灰白块：备用按钮／文本按钮缺少明确的原生 disabled 状态背景和文字规则，已在 auth 局部补齐；须真机回归。
- 目前没有完整的注册防刷系统，不能把微信身份、手机号验证或客户端 processing 锁等同于防刷。

## 昵称展示规则与核验范围

注册上限、视觉显示宽度和身份唯一性分别管理。不得以最窄卡片能放几个字直接推导全站合法昵称长度，也不得通过裁剪存储内容避免溢出。

| 场景 | 规则 | 当前需核验消费者 |
|---|---|---|
| 注册、账号资料 | 同一长度与 Unicode 计数规则；超长阻止保存并说明 | auth、account-profile、两个后端入口 |
| 双列作品卡、紧凑作者行 | 单行省略；头像与操作不被挤掉；进入主页可看全名 | work-card、discover、search-results、me-assets、creator-content |
| 个人中心、创作者主页 | 完整昵称有可访问位置，必要时换行；身份标签不参与昵称截断 | me、creator-profile 模板、provider-detail |
| 工作台欢迎语 | 问候语允许换行；不改变昵称实体值 | discover provider 分支、provider-home |
| 订单、预约、协议、评价 | 姓名与 UID 分开布局；禁止昵称挤掉订单状态、金额或 UID；全名可查看 | booking、booking-status、order-detail、orders、provider-orders、provider-request、provider-task、fulfillment、review |

覆盖320/375/390/414宽度及大字体，样本包含20汉字、20宽英文、混合字符、组合字符和表情。完成实际测量后确定是否调整注册上限；已有账号不得静默裁短。

## 审核与反滥用方案

1. 注册与改名都在服务端执行昵称审核，前端提示不构成安全边界。使用可信微信身份，不接受客户端指定 OpenID。
2. 建议使用微信文本内容安全能力，配合少量可解释的平台规则（如冒充万匠屋官方）；只在明确通过后创建账号或保存新昵称。接口故障、超时、需复核不能直接放行。
3. 拒绝提示：昵称暂不能使用，请修改后重试。服务不可用提示：昵称审核暂不可用，请稍后重试。区分两种原因，保留输入，不创建半成品账号。
4. 改名被拒时保留原昵称；存量违规昵称另走通知、修改与人工申诉流程。处置强度与申诉通道待运营确认，不自动永久封号。
5. 开源词库仅作候选补充。houbb/sensitive-word 的引擎与词库已拆分，实际引用前须分别核查许可证、来源、版本和误伤情况；不把词库命中直接等同于违法判断。尚未下载或接入任何词库。
6. 防刷待实现：服务端限频、重复注册幂等、跨实例一致的失败计数与限流、异常请求审计；必要时对高风险尝试增加验证。阈值、费用和用户恢复方式需实测，不在本文虚构上线完成状态。

## 两种注册流程

- 微信注册：阅读协议与隐私政策 → 填昵称 → 微信可信身份校验 → 昵称审核 → 创建或返回已有账号。不因用户拒绝绑定手机号就伪造手机号。
- 手机号注册：同意相关用途 → 验证手机号 → 昵称审核 → 创建或关联账号。微信手机号授权与自建短信两种实现已询问用户选择；同号与微信绑定冲突须明确处理，禁止自动合并他人账号。
- 无论哪条入口，都先完成必要校验，再落库同意的协议版本、时间与账号关系。更新法律文本不能继续用旧版本号证明同意。

## 长文展示方案

注册页分别链接《用户服务协议》《隐私政策》《账号与昵称规范》，默认不勾选。每份采用独立可滚动全文页面：标题、版本、日期、目录、分节正文、重要条款提示、返回入口。点击链接只阅读，不等于同意；返回后保留昵称和注册方式。正式版协议可在个人中心再次查看，用户能查到其同意版本。

不把整份协议放进 showModal；不强制滚动到底来冒充充分同意。现阶段本文件是审阅稿，不能写入 account-use-v1 后直接发布或要求用户接受未定条款。

## 《账号与昵称规范》正文初稿

1. 昵称用于公开展示，请避免输入身份证号、手机号、家庭住址等私人信息。昵称不作为账号唯一凭证，平台通过稳定账号标识区分用户。
2. 不得使用足以使他人误认的平台官方名称、未经授权的机构标识或他人身份；不得通过昵称实施欺诈、侮辱、侵权、骚扰或发布违法违规内容。
3. 昵称须满足统一长度和字符规范。昵称完整值保存在账号资料中；紧凑列表可省略展示，完整资料及合作身份确认处应提供可查看的完整信息。
4. 注册、改名都需检查。未通过时会提示修改；服务异常时会提示重试。审核提示不代表对用户作出违法认定。
5. 改名不得规避既有处理或冒充他人。历史订单应保持可追溯的账号标识，不能因改名失去合作方身份关联。
6. 对误判可申请人工复核。正式申诉入口、处理负责人及期限需在发布前补齐；本审阅稿不承诺尚不存在的处理能力。
