## 2. 支付可行性：微信单端已确认，支付宝路径待证

2026-09-05 核验的官方常规路径：

- [微信支付接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4015459512) 要求相应小程序认证、支付权限和商户 AppID 绑定；[开发指引](https://pay.wechatpay.cn/doc/v3/partner/4012076732) 描述小程序调起微信收银台后由服务端查单／回调核验。
- [支付宝小程序支付文档](https://opendocs.alipay.com/mini/api/openapi-pay) 对应 my.tradePay；官方文档仓库的 [小程序支付常见问题](https://github.com/AlipayDocs/open-docs/blob/main/support/支付宝小程序/常见问题/小程序支付常见问题.md) 描述服务端建单、客户端调起及服务端查询确认。
- 这些文档分别面向各自宿主，不能据此推出微信小程序已具备原生支付宝支付的通用接口。本轮未核实到该通道，不把“微信内双支付按钮”当成已经可实施的方案，也不以搜索未发现证明所有可能通道绝对不存在。

用户已选择“只做微信小程序，继续核验支付宝可行路径”。不新建支付宝小程序，不将跨端账号绑定列为既定开发需求。以下是可行性分类，候选路径尚未获准实施：

## 7. 历史规则的替代与待决边界

1. **项目槽位**：旧 FR-06 的预设职业槽位／缺人提示被后续 D-006 与 UI 标准 10.3 的执行订单连续列表替代；不重建旧槽位。项目只管理，不推进订单。
2. **沟通方式和执行入口**：旧 PRD 的沟通方式待定、纯确认后执行，已由 UI 标准 9.6／支付规则收敛为站外联系、四项确认、必要 NDA、买方确认及服务端核验付款。支付门禁继续有效。
3. **Brief**：当前 D-007 是从历史预约整理草稿；它只证明该流程被确认，不足以认定原智能抽取能力整体取消。AI 提取是否进入首发仍待决定。
4. **毛娘履约**：旧 PRD 标记待定，当前代码和 9 月 3 日交付日志按现场类处理；尚未找到足以替代业务确认的明确决策，本轮不把实现当确认。
5. **普通平均分与综合评分**：普通平均分实现为完成单有效评价平均、保留一位小数；它不证明综合评分窗口／权重和热门标签算法已获批准。
6. **作品码唯一性**：服务端短哈希稳定生成不等于严格唯一性约束；删除后的历史引用规则原本待定，仍保留待决。
