## 2. 版本管理与回退边界

- 根目录 Git 为 2026-09-05 新建，管理根文档、产品记录、设计资料和小程序；首个提交是当前文件快照，不是历史恢复，也不证明快照内功能全部通过验收。
- `prototype/` 保留原有独立仓库，当前历史 HEAD 为 `9846671`（2026-08-17，发布 20 Full Prototype v0.6.3）。已有未提交／未跟踪文件仍在原处，不能用该 HEAD 代表当前原型工作区，也不能直接重置回该提交。
- 根 `.gitignore` 排除 `prototype/`、依赖、云凭据、私有配置、截图审计输出和秘密文件。原型文档中的本轮增量仍属于原型仓库，不由根提交保存。
- 查看后续变更：根目录运行 `git status`、`git diff`；原型目录单独查看。若沙箱出现所有权提示，只对当前调用使用精确 `safe.directory`，不全局信任所有目录。
- 代码回退须先保存新产生的改动，再对明确文件恢复到指定提交；禁止用全目录硬重置覆盖用户工作。云函数回退需对应代码和部署配置，数据库迁移需单独评估兼容与恢复，不随 Git 自动回退。
- 本轮仅建立本地基线，没有添加远端或推送；远端备份、原型当前工作区快照与真实恢复演练仍待后续工程任务。
