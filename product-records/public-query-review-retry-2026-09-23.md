# 公开查询与审核重试修复（2026-09-23）

本轮从 A03、D01、D03、F05 待办继续实施明确缺陷修复。修改限于后台和本地测试，无新页面、云资源或部署。

## 已完成的本地修改

1. 公开档期：先检查目标账号 ACTIVE，再检查发布快照基本结构；没有快照时才允许旧 PUBLISHED 资料。隐藏、停用、注销或基本结构损坏的目标返回 TARGET_NOT_PUBLIC，在拒绝前不读档期与订单。匿名查询正常公开服务方保留；getMine/saveMine 仍允许有效账号编辑未发布档期。该错误加入入口白名单。
2. 目录隔离：读取快照后，先验证服务／作品项、图片与关联 ID 数组、服务区域对象、置顶数组及价格／版本／时间等已使用字段。损坏的快照被隔离，不使其他服务方的列表查询失败，也不恢复该作者旧目录。不是完整业务 schema 校验或数据库分页。
3. 目录统计：可写字典改为无原型字典，作品 ID 为 __proto__、constructor、toString 时引用数不再变为 NaN，也避免分组及关联字典的原型属性碰撞。
4. 审核重试：ERROR -> SUBMITTING 条件更新必须实际命中才能继续调用存储和微信审核；输掉竞争的请求返回 MEDIA_STATE_CONFLICT，避免并发重复提交。十个并发重试的本地状态模型验证仅一次外部调用，最终保留获胜者 trace。
5. 审核失败落库：删除对任意错误正文的正则脱敏存储，改为仅持久化固定错误码与有效的数值渠道码。未知消息、手机号／token 等正文、对象和循环错误码均不落库；不会因循环对象导致序列化失败而留在 SUBMITTING。不会清理已存在的历史记录。
