# 资金页真实付款记录 — 2026-09-05

## 范围与当前结论

自动推进由 `.10` 的支付记录基础续接。F07 核对发现到场预约时段与线上后期截止日期的占用含义尚未收口，已提出一个待答问题：到场服务具体时段互斥、线上后期截止日期允许重叠并由服务方确认，还是所有职业均按时段互斥。未把等待时间当成确认；依赖这一决定的防撞单写入暂不实施，继续不依赖它的 P07 资金读取。

`.11` 完成资金页的本地云端读取链路，未完成真实结算、退款或提现。移除生产资金页对 v063-store、固定演示服务方和本地余额的读取；复用已有 order-api 与 provider-request 详情路线，没有另建钱包、账单页或充值系统。

## 数据、权限与页面对应

| 环节 | 规则／实现 | 页面结果 |
| --- | --- | --- |
| 进入资金管理 | 由云上下文解析本人账号，检查 PROVIDER 能力；请求中的 providerId 不作为归属依据 | 仅呈现本人服务方付款记录；未登录／无资格／读取失败有明确提示 |
| 获取记录 | 0018 order_payments 通过现有 order_payment_order_fk 关联 order_aggregates，限定订单 provider_id；只选 PAID／PAID_REQUIRES_REVIEW | 显示付款已确认或付款待核对；待支付／已关闭不冒充到账 |
| 校验与裁剪 | 检查到账交易号、时间、整数金额、币种和关联归属；正常 PAID 要求应付与到账总额一致 | 返回显示所需字段；不返回微信付款人、交易号、商户号、内部核对原因或订单其他私密字段 |
| 金额性质 | 返回付款记录总额及实付；当前结算能力明确 UNAVAILABLE，可提现值为 null | 顶部显示结算待开通，绝不把付款总额称为净收入或把未知余额显示成零 |
| 继续加载 | 每页 20，以付款时间和支付 ID 的双字段游标取下一页；同时间记录不漏，返回最多 21 判定后续 | 整行点击进入既有服务方订单；加载更多失败保留已有记录，可重试 |
| 刷新／重进 | 每次读取绑定当前请求序号，过时分页响应不能覆盖新刷新；重进从当前身份重新读取 | 加载、真实空态、失败、成功、分页结束明确区分，无云端失败后回退演示数据 |
| 收款资格 | 仅读本人 provider_payment_merchants 的资格快照，未开始／待核验／已核验／暂停分别返回 | 展示当前收款资料状态；资格已核验不等于支付、结算能力已经开放 |

不新增迁移，当前 18 个迁移中的订单外键已表达上述归属关系。资金读取使用 CloudBase MySQL 的关联查询与排序，不依赖跨表写事务；支付写入继续使用 `.10` 的原生 MySQL 事务。真正下单、验收分账和退款尚未开放。

旧 UI 规则要求可提现余额默认 0.00、充值／提现双按钮。依据本次用户完整交易与三层对应要求、已确认平台逐笔分成方向及 P07 工作计划，已将公共 UI 规范的资金两条规则改为真实付款记录与未知结算状态；同步修改资金、M01 和生产数据边界审计，旧规则不再作为新版验收标准。其余 M01 入口、身份切换和作品功能保持原状。
