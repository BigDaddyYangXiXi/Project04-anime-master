# 提现已付金额的回单证据校验

## 后续横向检查：失败终态与写入端

同日追加：真实本机 MySQL 先复现单独把付款改为 FAILED、没有失败回单时，旧预留函数仍允许第二笔付款。失败证据 `.artifacts/withdrawal-terminal-before-20261003.txt` 显示 Missing expected rejection。

已将终态校验提取为 withdrawal-receipt-evidence，进度读取、付款预留（包含原请求重试）及回单登记共同使用。成功和失败均须唯一且内容匹配的终态事件；有终态证据却把付款状态倒改成 EXPORTED 等非终态也拒绝。FAILED 必须没有成功银行流水；正常经核验失败仍可在同一提现申请内重新预留，来源占用不会被释放到其他申请。UNKNOWN 继续占用。

修复后 26 项真实 MySQL、14 项单元/命令测试通过；新增无回单失败拒绝再分配、两种终态证据改动拒绝写入/重试、终态倒退不能追加回单。既有合法失败重试、10 并发回单、旧未知重试不回退成功均通过。预留受限测试账号新增回单表 SELECT 后通过，并验证不能修改摘要或删除回单；权限草案同步，生产新增权限尚未授权。证据 `.artifacts/withdrawal-terminal-after-20261003.txt`。测试库及临时账号清理，本机 MySQL 已关闭。

本段更新取代下文“仅成功状态读取”的实施范围描述。仍未部署、扩权或触及真实资金；到账账本、正式导出、账户核验尚未实现，不以这一组证据校验宣称完整资金闭环。

检查发现两个独立缺口：recordWithdrawalReceipt 只追加回单事件并更新银行付款条目，没有写入到账账本；readWithdrawalProgress 直接根据付款条目 SUCCEEDED 状态汇总已付金额，没有核对成功回单。本轮修复第二项，第一项继续阻断正式提现启用。

进度读取仍在同一 REPEATABLE READ 只读事务内。对每个成功条目，要求恰好一条成功回单，商户与当前公司范围一致，存在银行流水引用；用申请、付款、服务方、账户版本、精确分金额、原操作人、成功状态、原证据引用、AppID、商户及银行流水重建摘要，与原回单摘要比较。不符则拒绝返回进度，不将无证据的状态计入已付，也不改动数据或释放占用。

回单摘要提取为 writer/reader 共用函数，保留原字段顺序、空银行引用规则及 SHA256 格式。历史已存摘要无需迁移。此为内部证据一致性校验，摘要不是数字签名，不能抵御有权限同时篡改全部明细和摘要的操作者，也不验证真实银行回单；受限权限及实际银行核对仍不可缺少。

验证：14 项输入、命令、读取及旧格式兼容单元测试通过；24 项真实本地 MySQL 测试通过。新增缺回单、已付金额改动、账户版本改动、回单引用改动拒绝；既有测试中的成功状态样本改由真实本地回单 writer 写入，保留部分到账、超安全整数精确读取、并发、隔离和冻结测试。证据为 wechat-miniprogram/.artifacts/withdrawal-receipt-evidence-mysql-20261003.txt。隔离库由测试清理，本机 MySQL 已关闭。

到账账本剩余工作不能由本轮替代：需要成功付款按原提现收入来源分配冲销净额负债，成功回单、冲销分录及来源分配同事务提交；重试不得重复，处理中/未知不得冲销，失败不得记已付。多来源及部分付款必须逐来源守恒，并与当前资金审计、余额读取共同接通。现有渠道应收不等于银行存款，不能把银行付款直接冲减微信渠道应收或随意新增现金余额。实际银行对账仍需单独核实。

本轮仅本地实现，未生产部署、迁移、扩权或处理真实资金。新读取依赖 0050 回单表的 SELECT 权限和新共用模块，部署时须完整打包并复核前置；不得单独覆盖 reader。现有预检、本人核验、正式导出、到账账本与真实收款验收仍待完成。
