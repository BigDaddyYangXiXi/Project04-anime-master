# Anime Master Design System

> 内容长度、输入校验与文本溢出统一执行 [CONTENT-LENGTH.md](./CONTENT-LENGTH.md)。任何动态字号或字数上限调整都必须先更新该规范，再同步到 Figma 与微信小程序实现。

> 适用范围：微信小程序产品原型、互动线框和后续 Prototype 合并。页面级覆盖文件位于 `pages/`；没有覆盖文件时执行本规范。

## 产品与平台

- 产品类型：动漫创作服务市场，连接需求方与妆娘、毛娘、摄影、后期等服务者。
- 平台：微信小程序；不是通用 H5、桌面 Web 或独立 App。
- 设计目标：先理解作品、服务者、地域和时间，再完成预约、订单与项目协作。
- 视觉方向：内容优先、轻量、低动效；本地 0.7 使用“彩虹果汁软糖史莱姆”主题。糖果色负责品牌、导航、重点状态与少量高层卡片，交易正文、表单和金额继续使用白色／近白内容面。

## 本地 0.7 彩虹果汁软糖史莱姆主题

本节依据 2026-08-17 用户最新明确指令建立，覆盖旧契约中“彩虹只作为史莱姆边缘材质、页面不彩虹化”以及“统一使用线性图标”的限制；0.6.3 的页面尺寸、组件结构、语义状态和微信平台边界不变。

| 令牌 | 色值 | 角色 |
|---|---|---|
| Coral Juice | `#FF6F71` | 找高手、预约／沟通、主品牌 |
| Gummy Orange | `#FF9B4A` | 工作台、提醒型重点 |
| Lemon Jelly | `#FFD85A` | 项目、引导与轻提示 |
| Soda Sky | `#73C9ED` | 订单、交付信息 |
| Mint Slime | `#65D5BD` | 档期可约、成功辅助 |
| Berry Pink | `#FF88AE` | 我的、评价与公开展示 |
| Rainbow Lilac | `#D5B9F4` | 仅用于史莱姆彩虹轮廓的一小段，不作为页面主题或操作色 |
| Ink Plum | `#4B3048` | 主文字与图标深色轮廓 |

- 图标采用可编辑 SVG／组件源：桃色软糖本体、内层彩虹环、外层白色贴纸边、莓果色细节、单一高光和极简表情；避免高纯度黑色和近黑描边。
- B01 职业入口保持 66px 紧凑图文结构。选中态只在 44px 职业 Icon 外增加 2px 主视觉低饱和彩虹细圈和 2px 暖白外圈，不包文字或整颗按钮；字标保留珊瑚渐变底，两个汉字使用独立高低差与轻微相反倾角形成圆润字形节奏。
- 底栏“找高手”必须直接使用主史莱姆母形；订单、项目、工作台、档期和我的从同一轮廓、线宽和高光规则延展。
- 主要图标在规定容器内占满 30×30px 视觉区，按钮通过父级保证至少 44×44px 热区；不得溢出、贴边或依靠透明留白伪装尺寸。
- 同一页面最多让一个高层主视觉使用奶油黄／珊瑚／薄荷的低对比渐变；普通按钮和状态卡使用珊瑚相邻色域。禁止紫色主题卡、紫色主按钮和橙紫渐变。
- 正文对比度与业务状态优先于主题色；成功、警告、错误不能只依赖彩虹色表达，必须同时有文字或图形。

|---|---:|---|---|

| Nav Title | 17/24 | Medium | 微信式顶部导航标题 |

## 空间与尺寸

- 基准画板：375×812；常规内容宽度 343，左右边距 16。
- 间距只使用：4、8、12、16、20、24、32。
- 相关元素间距 4/8；连续页面区块 8；控件组 12；独立区块间 16/24；页面大区块 32。
- 文字—文字：同一信息组 4px，标题—正文 8px；文字—图形：行内图标／头像 8px；图形—图形：同组 8px。
- 重复双列卡片横向间距 12px、纵向间距 16px；密集弹层分组可使用 4px，但同一层级不得混用 4/6/8px。
- 普通信息 Section 使用 16px 内边距；操作、字段和提示面板使用 12px 内边距；Hero 等重点面板使用 16px。
- 固定高度只用于触控目标、媒体比例、导航和明确视口；纯内容卡必须按内容自适应，不得把多余高度堆到最后一个元素下方。
- 固定高度控件允许出现由居中计算得到的非 token 值，例如 44px 控件内的 22px 文字对应上下各 11px；该值仅用于计算对齐，不得复用为通用间距。
- 标准按钮与输入触控高度不小于 44；相邻触控目标间距不小于 8。
- 圆角只使用：4、8、12、16。8 用于按钮和输入，12 用于普通卡片，16 仅用于 Hero、弹层或重点面板。
- 固定顶部导航和底部栏必须为滚动内容预留空间，内容不得被遮挡。

## 按钮与交互

- 每个页面最多一个高强调主操作；次要操作使用描边或低强调表面。
- 同一层级按钮必须等高、同字号、同字重、同圆角、同内边距。
- 标准整行按钮：343×44；内容卡内部按钮可以使用容器宽度，但高度仍为 44。
- 所有可见按钮必须具有真实跳转、弹层或状态变化；禁用状态必须同时降低强调并取消点击。
- 点击反馈 80–150ms；页面／弹层过渡 150–300ms。低保真阶段不添加装饰性动效。

## 页面结构

- 顶部：微信式状态栏和导航栏；非一级页面在固定位置提供返回。
- 中部：单一主滚动区，按“当前任务 → 关键条件 → 主要操作 → 次要信息”排序。
- 底部：一级页面显示固定底部导航，最多 4 项；子流程使用明确的返回路径，不把底栏当作返回。
- 图片型作品集合使用双列；订单、项目、服务项目等任务对象使用单列卡片。
- `WorkCard` 为 166×248px 基准：标题—标签 4px、标签—价格 4px、价格—底边 8px；双列横向间距 12px、纵向间距 16px。
- `ContentCard` 上下左右内边距 16px、标题—正文 8px并按内容自适应；单行正文 84px，两行正文 104px。
- `Field` 使用 18px 标签、8px 间距和 52px 控件，内容自适应总高 78px。
- `CareerChip` 使用上下 8px、24px 图形、4px 图文间距和 22px 标签，内容自适应总高 66px。
- 地域、时间、职业和筛选使用轻量控件或底部弹层，不堆叠成多个大型装饰卡片。

## 原型组件与微信生产组件

- Figma 的 `PickerOption`、`SelectionChip`、`SheetSection` 及其变量、预设选项，只负责验证选择、取消、确认、回填和返回上下文，不作为生产数据模型或可直接打包的组件。
- 正式微信小程序中，地域优先使用 `<picker mode="region">`；日期和时间使用 `<picker mode="date">`、`<picker mode="time">` 或 `picker-view`；多选筛选使用 `checkbox-group`、原生 `button`，或以 WXML/WXSS 封装的合规自定义组件。
- 底部弹层应按小程序原生层级、安全区和滚动规则实现；只有出现原生组件层级覆盖问题时才评估 `cover-view`，不得默认使用。
- 合并 Wireframe 到后续 Prototype 或生产代码时，必须在合并清单中加入“测试组件到微信原生组件映射”和真机复验结果。

## 禁止项

- 不使用英文 Web 字体替代中文产品字体。
- 不使用 Emoji 或字符符号作为结构性图标；统一使用本地 0.7 可编辑 SVG 史莱姆贴纸图标体系。
- 不把所有内容都做成卡片，不使用无意义阴影、渐变、玻璃效果或悬浮大圆角容器。
- 不因低保真删除历史确认的功能、弹层、状态、跳转或返回关系。
- 不在同层级混用 13/14/15px 按钮文字、不同高度或不同左右内边距。
- 不照搬 UIZZE 参考的品牌、文案、图片或具体像素布局。

## 验收标准

- 41 个画板保持 375×812，不出现横向溢出。
- 页面文字全部使用明确的 `Wireframe/*` 文字样式或受已验证组件控制。
- 所有标准按钮高度 44、文字 14/20 Medium；触控区域不小于 44×44。
- 顶部导航、返回位置和固定底栏跨页面一致；主滚动内容不被遮挡。
- 所有可见交互有有效目标，返回后保留必要上下文。
- Prototype 与 Wireframe 版本独立记录，合并时使用显式清单。
