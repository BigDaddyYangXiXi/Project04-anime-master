# Anime Master 内容长度与排版规范

> 适用范围：Prototype、Figma 互动线框、微信小程序生产实现。所有新增或修改的文本、输入、标签和按钮都必须先映射到本文件中的语义角色，不允许只凭视觉临时决定字号或长度。

## 1. 计量方式

同时执行“可见字素数”和“加权单位数”校验：

- 中文、日文、韩文、全角字符、Emoji：每个可见字素计 2 单位。
- 英文字母、数字、半角标点、半角空格：每个字符计 1 单位。
- 输入前后空白不计入内容，提交前必须 `trim`；仅空白内容视为 0 个可见字素并拒绝提交。
- 换行计 2 单位；不允许换行的字段在输入阶段移除换行。
- 组合 Emoji 按一个可见字素处理，不能按 Unicode code unit 截断。
- “最多 10 个中文字”等价于最多 20 个加权单位；英文、数字和半角符号可在同一 20 单位预算内混排。

推荐实现：使用 `Intl.Segmenter` 按 grapheme 分段，再按上述规则累加单位；微信基础库不满足时使用经过测试的 grapheme splitter。Figma 只表达规则和边界样例，真正的输入阻止、计数和错误提示由小程序实现。

### 2.1 文字垂直度量与对齐

文字排版必须区分“排版行框”和“字形真实边缘”，禁止直接用随机文本节点框做视觉对齐：

- 标准排版行框：页面标题、正文、按钮、标签、字段、价格和导航默认使用 `Leading Trim = NONE`。单行文本节点高度必须严格等于对应样式行高，例如 12/18 的节点高为 18px、14/22 的节点高为 22px；容器内使用垂直居中。
- 多行排版：保留样式行高控制基线间距，文本高度由实际行数计算；不得为了“贴字形”压缩行高，也不得把多行文字强制成单行高度。
- 图形边缘对齐：动态文字仍使用 `Leading Trim = NONE` 和完整语义行框；通过专用外层容器与经边界字形验证的光学偏移对齐，不得使用 CAP_HEIGHT 紧框裁掉英文下降部、抗锯齿像素或字体回退字形。
- WorkCard 作者 ID 的批准实现为：Noto Sans SC Regular 11/16、文本节点 `118×16px`、作者行 `166×24px`、文本 `x=40/y=10`、Avatar/24 `x=8/y=0`，头像—文字水平间距 8px，作者行 `clipsContent=false`。该偏移仅属于 WorkCard 组件，不得传播到其他文字角色。
- 禁止将动态文字转轮廓、拉伸字形或按某一条示例文案硬编码黑色像素边界；中文、英文、数字和带下降部字符必须继续保持可编辑和可替换。
- 组件优先：先修正主组件文字节点，再由实例继承；不得逐个拖动实例制造不同的 y 偏移。

验收时检查“单行节点高度 = 样式行高”，并用中文、emoji、英文下降部字母 `g/j/p/q/y`、数字及最大长度样本验证：字形不裁切、父级不裁切、视觉边缘与目标图形一致。

## 4. 动态调整规则

1. 先确定语义角色，再确定字号；不得为了塞入文案随意从 14px 降到 12px。
2. 可动态调整的是容器宽度、行数、文案和字段上限；字号只能切换到本规范中另一个有明确语义的角色。
3. 修改任一字段上限时，必须同时更新本文件、Figma 规范说明、输入组件校验、回显组件和测试样例。
4. 双列卡片固定使用紧凑角色；单列详情卡可使用标准卡片标题，不允许同一层级混用 13/14/15px。
5. 所有新字段必须在 PR/合并清单中声明：语义角色、最小值、最大值、是否允许换行、溢出策略和错误提示。

组件高度不得反向决定文字间距：WorkCard 按内容计算为 248px，价格行到底边 8px；ContentCard 使用 16px 上下内边距与 8px 标题—正文间距，单行／多行正文分别由 Auto Layout 自适应为 84px／104px。

## 5. 微信小程序落地

- 原生 `input`/`textarea` 的 `maxlength` 只能限制字符数量，不能直接表达上述加权单位；生产实现必须在 `bindinput` 中按可见字素和加权单位二次校验。
- 地区、日期和时间沿用原生 picker；Figma 中的选择组件只用于验证流程。
- 所有可交互文字控件的可视高度可以小于 44px，但外层点击热区必须至少 44×44px，且相邻热区间距至少 8px。
- 必须覆盖测试：全中文、全英文、数字、混排、Emoji、组合 Emoji、前后空白、仅空白、刚好上限和超过上限一个单位。
