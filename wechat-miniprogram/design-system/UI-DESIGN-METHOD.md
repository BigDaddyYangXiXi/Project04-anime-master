# UI设计方法：先建立视觉秩序，再实现

2026-10-07建立。用户要求通过可靠方法论形成稳定判断，停止“先做页面、再由用户逐项纠错”的循环。本文件是本项目UI工作的必读规范，与tokens、业务契约配合使用；不建立第二套设计系统，不授权全站重画。

## 1. 学习依据与适用边界

以下为本次实际查阅的公开原文。只提炼方法，不照搬其他产品样式。

| 来源 | 提炼的方法 | 项目运用 |
| --- | --- | --- |
| [NN/g：视觉设计五原则](https://www.nngroup.com/articles/principles-visual-design/) | 比例、层级、平衡、对比与格式塔共同组织视觉 | 先决定主次，再分配面积、字号、颜色与位置；不是所有区域同等抢眼 |
| [NN/g：视觉层级](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/) | 内容优先级应先于视觉设计；缩小或模糊观察可帮助检查焦点和分组 | 先写阅读顺序，完整图复审实际焦点；此自审不是用户研究的替代品 |
| [NN/g：相似性原则](https://www.nngroup.com/articles/gestalt-similarity/) | 外观相似会使人预期含义或行为相关 | 同类计数、入口保持规则一致；不同交互不能只因“整齐”而变得难以区分 |
| [IBM Carbon：间距](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview) | 距离表达关系；重复间距形成秩序；空间也能建立分组与重点 | 优先用对齐和距离表达结构，必要时才加容器；不机械追求越挤越好 |
| [NN/g：美学与最小化设计](https://www.nngroup.com/articles/aesthetic-minimalist-design/) | 删除低价值干扰，同时保留完成任务所需的信息 | 检查标题、说明、边框、装饰的作用，不删必要标签、反馈与状态 |
| [NN/g：图标可用性](https://www.nngroup.com/articles/icon-usability/) | 图标首先应传达含义；陌生图标存在歧义，需要可见文字 | 使用能快速识别的图形，控制一致笔画和光学大小；不为了点缀堆出新层级 |

上表之后的流程、检查门槛和项目实例是结合本项目问题制定的操作规则，不冒充原文结论。16px内距、12px组距或数字在上均不是普遍美学定律。尺寸沿用项目token，在具体信息关系与可读性中选择。Apple布局页本次未读取到正文，不用其作为已核实依据。

## 2. 动手前必须回答的六个问题

1. **任务**：用户打开此页要完成什么？哪件事最急、最常用？业务必要性、当前状态和频率决定位置，不按我写代码的顺序排版。
2. **阅读顺序**：先看到什么、再看什么、最后看什么？预先写出三层顺序，并找出主动作或主要入口组；导航页不强迫只剩一个按钮。
3. **最少信息**：完成任务至少需要哪些字段？一个计数只有“数字＋名称”，默认先用这两项成立布局，不先加图标、标题、副标题。
4. **关系**：哪些信息属于同一对象，哪些模块同级？先确定对齐线、组内距离、组间距离；没有关系区别就不任意改变数字顺序、文字位置或样式。
5. **参照**：已有项目模式或用户参考图中，哪一个具体结构解决相同任务？解释其适用原因及不应照搬的部分，不拿配色相似当理由。
6. **范围**：这次改哪些共用模块、哪些角色？哪些业务/原生控件保持？按影响清单检查，不借“统一美学”越界重设计。

结构重做时，将上述答案写成一段短契约，先对照一个更简的排列方案。比较的是信息层级和占用空间，不生成多套装饰稿。仅修改某个文字/间距时，复用已有契约，不重复调研和写长计划。

## 3. 构图与视觉节奏的判断顺序

### 信息与比例

- 先使用内容和位置建立优先级，再用字号/字重/对比加强。不能让设置、空标题或装饰比主要任务更显眼。
- 检查每个模块相对于其信息量所占的面积。简单信息不因套了卡片就获得大面积留白；重要内容也不能为了首屏“塞得下”被缩成小字。
- 对长名称、真实零值、较大数字、加载与失败分别验证。不能靠空数据截图证明密度合理。

### 分组、对齐与空间

- 同一对象的数字与名称、标签与字段，应比无关对象在视觉上更紧密；边界也参与分组，不能只套一个固定间距公式。
- 同级模块使用稳定的左右起点、列宽、文字基线和空间节奏。列表优先连续排列，真正独立的内容对象才考虑独立卡片。
- 卡片内部padding、按钮内部padding、外部margin分别计算。不得叠加三套间距后只检查每一个数值都“符合token”。
- 节奏来自重复的结构与少量有意义的变化。不能每组都加标题、边框、图标、橙色数字；也不能把所有元素挤成相同灰色。

### 字体、图标与颜色

- 同一语义类别先共用阅读顺序、字号和行高。允许有依据的角色变体；禁止计数上一组在上、下一组在下却没有理由。
- 添加图标前回答：能否更快识别？是否传达状态或操作？是否承担明确的品牌表达？若只是重复紧邻文字且增加一行高度，先不用。
- 图标统一笔画、视觉尺寸与对齐方式；框尺寸相同不等于光学重量相同。保留含义必要的文字，不用表情符号替代功能图标。
- 重点色分配给少数明确的动作/状态；不可点击文字与链接的视觉提示要能区分。降级辅助文字时不能牺牲阅读对比。
- 中文按语义写完整句子，用连接词、书名号和标点组织协议；自然换行，不用强制分行或额外空白代替标点。

## 4. 交付前自审：必须由执行者完成

| 检查 | 自审动作 | 不通过的表现 |
| --- | --- | --- |
| 焦点 | 看完整页面及缩小画面，对照预设阅读顺序 | 次级设置/装饰先吸引注意，主入口不明确 |
| 减法 | 逐项尝试拿掉标题、图标、说明、边框，判断信息损失 | 说不清用途仍因“丰富画面”保留 |
| 同类比较 | 并排检查所有计数、入口、身份、金额及相关角色 | 数字顺序、间距、图标样式无依据变化 |
| 空间 | 核对实际边缘到文字距离和总模块高度，比较改前改后 | 两个字段堆成三四层、删除标题后仍有空槽 |
| 可读与可点 | 窄屏、长文、字体放大；核对截断、触控与识别提示 | 为压高度缩小文字/热区，入口看起来不可点击 |
| 状态与后续 | 零值/未知/错误、点击后去向及返回；供需身份 | 零值冒充未读数据，空壳按钮，返回状态丢失 |
| 证据 | 标明完整图来源、版本、身份与状态，查看实际结果 | 只报测试数量/编译通过，没有看完整画面 |

任何一项明确失败，先修正再交付。不以“24组截图生成成功”或检查脚本通过替代审美判断；脚本只能证明它真正检查的尺寸/逻辑。网页映射不等于微信原生渲染，原生证据缺失必须明确保留待验收，不擅自绕过工具授权。

## 5. 已发生错误，转成可迁移规则

| 本项目反例 | 违反的关系 | 下次在何时截住 |
| --- | --- | --- |
| 收藏被堆成图标→名称→数字三层 | 表达成本大于信息量；与上方计数顺序不一致 | 设计前最少信息比较＋交付前同类比较 |
| “合作概况／我的收藏”重复解释已明确内容 | 无新增信息却增加高度 | 减法自审；不是以后所有标题都删除 |
| 大卡片、大组距和按钮内距一起叠加 | 对局部token合规，却没检查整体密度 | 计算最终边距与模块高度，查看完整页面 |
| 协议按钮各占一行，正文用触摸高度 | 把交互尺寸混成文本排版规则 | 文案语义＋正文行高检查 |
| 接到“图标点缀”就给每项加图标 | 把表现手段误当目标 | 先解释图标的识别价值，再选择出现位置 |
| 每次修改直接上传 | 用户仍在调整时制造版本成本 | 本地检查/同步后停止上传，按用户明确要求发布开发版 |

还要避免反向错误：为了统一计数样式，让可点击收藏与不可点击统计完全无法区分。后续复审须检查可发现性，在不恢复三层装饰的前提下处理；本次规范工作不顺带修改页面。

## 6. 学习和执行方式：少而持续，不堆材料

- **学习单位是一个问题。** 遇到陌生布局，先读对应原始方法，再拆解一两个任务相近的真实界面，写明“为什么有效”；已有可靠模式就复用，不每次重复全网搜索。
- **形成一条可检验规则。** 把原则转成具体的设计决定和失败条件，保存在该页契约或本文件；不能只摘抄“现代、简洁、美观”。
- **先自我反驳。** 问“更少元素能不能完成同样的事”“哪个局部抢错了注意力”“同类模块是否用了两套规则”。由我完成这一轮，不把用户当基础错误检查员。
- **记录证据而非自评。** 写出发现并修正的问题、完整画面位置、未验证项；不打自创美学分数来声称合格。
- **控制成本。** 不批量造无关方案，不因审美修复重跑全项目测试，不重复读取旧材料；做与影响面相称的检查。仅规范修改不构建、不部署、不上传。
- **后续接手可执行。** AGENTS与设计README必须指向本文件。用户新决定优先；更新冲突规则，避免不断追加互相矛盾的“最终方案”。规范固化执行方法，不能声称读过文章就已完成所有页面的美学验收。

## 7. 内容和深层流程验收（2026-10-07用户明确标准）

用户要求：页面上线后，信息必须对用户有帮助，并能按正确逻辑理解。页面数量、能点击、无溢出不能证明达到此标准。

- 每页回答：这是什么、当前状态、我能做什么、前置条件、操作后果、失败出口。只写与当前任务有关的内容，不把六项变成固定装饰标题。
- 帮助文章逐题作答。发布、响应、付款、退款、收款必须分别说明路径、条件和结果；禁止只换标题、复用同一段概述。
- 入口一直检查到用户拿到结果。已有页面可复用，但必须实际核对其内容和返回；“跳到已有页面”的占位说明不算用户路径验收。
- 列表、详情、表单、确认、结果、返回使用同一实体。用户输入的评分、金额、说明必须前后一致；申请成功不能写成业务处理完成。
- 先读当前业务契约与实现再填内容：评价字数/是否选填、发布后能否修改、资金含义、可退款阶段、登录和核验方式等不得随意假设。
- 未开放能力提供真实可用的替代路径，不假画“发送短信成功”“已换绑”“可提现”。原生权限与支付由平台完成，设计稿清楚说明衔接边界，不伪造授权或支付成功。
- 文案与最新决定冲突时，列出精确差异并补拟修订稿；不能直接把旧协议当作正确内容，也不能把拟修订稿说成正式生效文本。
- 验收至少走一条正常路径及对应失败/受限路径，并做相关身份的横向复核。提出修改、重新交付、验收、退款等要检查后续状态，不能停在按钮变色或提交弹窗。
- 分开报告内容方案、原型验证、真实服务实现、上线验收。运营受理和后台能力未接通时，不得因设计稿完整而声称可以上线。

## 8. 用几何数据和现有能力验收方案

- 对应当对称的框体，实测内缘至首尾内容行框的上下距离，差值超过1 CSS px必须解释或修正。不要只看padding声明，必须计入子元素margin、行框、空节点和gap。
- 单独检查页面边缘、卡片内距、组件间距；独立行不能重复缩进。结果居中和普通表单自然余白分开判定。
- 按窄屏/标准/宽屏与双身份记录结果，注明测的是哪些状态；几何合格不替代完整画面与真实行为验收。
- 每项设计先映射当前源码、唯一客户端及历史决定，列出保留/局部改动/新增。旧页缺少的控件不能在新示意中无声消失。
- 现有状态机、权限、分页、草稿、版本校验与原生能力必须保留。审计夹具与过期路由不能当实际入口；新原型结果不代表服务已实现。
- 示例不完整时明确禁止据此替换已有页面；复用真实页，不另造缩水业务实现。详见product-records/me-design-dev-review-2026-10-07.md。
