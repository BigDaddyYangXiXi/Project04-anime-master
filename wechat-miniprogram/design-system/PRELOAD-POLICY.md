# 双身份信息预加载规则

2026-10-20用户要求建立全信息边界：打开小程序后默认覆盖需求方与服务方；已填写服务方资料的账号优先准备橱窗、订单。适用于新增页面和既有信息读取；未登记的信息默认按需读取，不自动加入预加载。

缓存对象、TTL、字节预算及淘汰遵循[信息缓存规则](CACHE-POLICY.md)；预加载与前台必须复用同一缓存，不能各存一套。

## 身份与触发

- 真实登录会话恢复、首屏成功显示后才开始可选预加载。启动身份校验、当前页面目录、必要定位属于前台请求，不是预加载；不得被可选任务抢占。
- 用当前账号服务器返回的橱窗元数据识别：`draftVersion > 0`或`hasPublication=true`，或当前账号已确认草稿版本大于0，视为有服务方信息，优先服务方队列。待审核/未发布草稿同样算；不是审核通过或公开发布资格。
- 尚未保存的输入不发额外请求或上传来识别身份。没有上述证据时按当前用户所选身份排序；不能只因具备服务方角色就认定已有资料。
- 本规则只改变预读顺序，不改变当前页面、默认登录落点、账号角色、发布状态或审核结果。
- 服务方优先：本人草稿文字→本人公开橱窗文字→订单列表→项目列表→共用资料→收藏关系。需求方优先：项目列表→订单列表→本人草稿文字→本人公开橱窗文字→共用资料→收藏关系。同一轮覆盖双身份，共用数据不重复读取。

## 全信息分类

| 信息 | 读取规则 | 成本及一致性边界 |
|---|---|---|
| 真实会话、账号限制、当前页必需信息、必要定位 | 前台按流程读取 | 不得为预加载延迟；授权遵循既有同意/拒绝流程 |
| 本人基本资料、昵称与头像链接、城市及职业偏好 | 先复用会话/有效缓存，空闲补本人资料 | 不额外定位；头像只解析当前本人所需链接，不主动下载图片 |
| 本人橱窗草稿文字、服务文字、作品文字及资源编号 | 双身份预读，已有资料者优先 | 原始草稿30秒共用缓存/在途合并；不在预读阶段解析图片、查询媒体状态；有效已确认空草稿零请求 |
| 本人公开橱窗文字 | 双身份预读，`images:false` | 明确未公开时零目录请求；不把本人草稿加入公开目录 |
| 本人订单列表 | 双身份共用预读，服务方优先队列靠前 | 现有30秒展示缓存；付款、退款、验收、占档等操作仍由服务器实时判断，不能用缓存批准业务 |
| 本人项目列表 | 双身份共用预读 | 复用现有5分钟缓存，不展开项目正文、全部关联订单或参考图 |
| 喜欢/关注关系 | 低优先级，共用读取一次 | 复用15分钟缓存；不连带预读所有收藏目标详情、作者橱窗或作品图片 |
| 首页首屏作品/作者 | 当前页面需要才读 | 仅公开目录；后台不预取其他职业、城市、日期组合或后续页 |
| 图片原图/缩略图、图集、视频、音频、附件、私有下载链接、水印导出 | 不预加载 | 可见图片按页面需求加载；私人媒体访问实时鉴权；不批量预签名/下载 |
| 项目正文、订单详情、私人联系方式、NDA、合作资料、交付/参考附件 | 不预加载 | 进入目标页按权限读取；取消此前“最近项目正文”后台预读 |
| 全量档期、历史订单、全部搜索结果、粉丝/收到互动/评价明细、其他作者详情 | 不预加载 | 按页需求读取，不展开列表或遍历分页 |
| 钱包、税务、银行卡、提现、付款/退款/结算/争议执行详情 | 不预加载 | 进入功能或执行动作时按既有实时校验读取；不得后台发起写入或资金操作 |
| 图片审核状态、接单资格、发布/退款资格等可变状态 | 不后台轮询 | 在相关编辑/发布/业务页面按原流程读取；已有审核刷新不扩大到启动流程 |
| 帮助、协议、静态图标/规则文案 | 使用随包资源；远程正文按需 | 不额外拉取全站静态资源；协议确认按实际版本执行 |
| 运营管理、审核队列、后台统计 | 不向普通用户预加载 | 保持运营权限入口边界 |

发布变更对照 `getWorkspaceReview` 仅在用户打开发布确认页时读取本人已公开快照，不纳入启动预加载，不解析媒体链接、不写入草稿。

## 调度和失效的硬约束

- 延迟800ms、串行执行六个逻辑任务；每项开始前让位于前台云请求和定位。每轮只在15秒窗口内发起任务，已发请求不强制撤销。
- 每项前检查网络：Wi-Fi/4G/5G可进行；无网、2G/3G、未知网络或检测失败不预读。网络类型不是实时带宽测量；不宣称能识别所有拥塞。
- 同账号同会话60秒内最多启动一轮，跨页面或切角色不重开队列。退出、切号、会话变化、后台状态阻止后续任务；失败静默、不自动重试，目标页正常读取仍可恢复。
- 保留各服务已有缓存期限、版本校验和写前/写后失效；原始草稿的缓存不包含媒体状态。审核中图片进入编辑页仍重新查状态，不能因预读把审核永久缓存。
- 六个任务不等于六次实际云请求：资料可能解析头像链接，后端现有列表还可能返回较多记录。本轮不新增分页遍历，也未完成服务端限量接口；大账号的响应体积/数据库成本须在既有D03容量任务中实测后收紧，不能宣称已具备字节或成本硬上限。

## 实现与验收

共用调度：`miniprogram/services/background-reads.js`；草稿文字准备：`services/cloud-catalog.js`；原始展示缓存：`utils/read-cache.js`。新增预加载必须更新本表并证明复用、失效、身份隔离及请求成本，不允许页面自行增加后台全量读取。

验证包含：未发布草稿识别为服务方优先、双身份只读一次、弱网停止、前台优先、切号/后台终止、草稿预读无媒体请求、前台合并及保存后失效。当前真机首开耗时、云端实际读取量与成本需另外验收；本地通过不等于性能目标已达成。

## 2026-10-21 橱窗档期页签

`provider-detail.loadStorefrontCalendar` 仅用户进入档期页签后按需读取，不加入预加载。本人用getMine、访客用getPublic；页内复用已取日期，切月不重复请求。失败不生成空档期，允许原处重试；返回结果核对账号、服务方和页面存活。不会读取媒体或触发资金动作。
