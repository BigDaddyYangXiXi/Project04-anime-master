# 全模块设计审查与整体收敛方案

日期：2026-09-09。依据：用户认可的作品详情关注／喜欢分工、统一设计规则、26 页模块目录，以及本轮微信开发者工具画面。

## 审查结论

**当前不通过整体设计统一性验收。** 作品详情的功能分工可以保留，但其他页面仍混用不同年代的颜色、文字等级、卡片、按钮和状态表现。主要问题是规则与实现未联动，不是缺少装饰。

本轮完成的是全模块审查与明确的整体验收方案，没有把以下建议冒充已落地的页面修改。设计值、业务页面、服务端与数据库未在本轮批量改写。

### 证据范围

- 本轮采集26个路由、30组页面／身份，每组包含顶部与滚动末尾，共60张原始视口截图。开发工具连接已经恢复。
- [采集记录](../.artifacts/module-review-2026-09-09/capture.json)记录请求路由与实际路由；[逐页截图索引](SCREEN-INDEX-2026-09-09.md)记录审查意见。兼容入口可能指向现有主页面，不虚增独立设计。
- 这是本地 audit 数据，包括历史日期、占位作品和以前测试留下的订单。不能评价真实作品摄影质量，也不能证明生产数据、付款或授权能力。首尾截图不是整页长截图，中间内容、弹层和状态仍需专项补验。
- 发现页第一次采集出现空白帧，已延长等待并重新采集；不把第一张空白帧直接定性为产品缺陷。
- 审查区分：**画面已见问题、源码已见差异、尚未取得状态证据**。没有给未看到的状态编造审美评分。
- UIZZE 本轮只取得公开首页，未取得3至5个可核验的具体应用实屏。Apple文档正文在当前网页读取方式下要求JavaScript，微信设计页未成功读取。故本轮不声称已重新验证最新官方规范或完成外部优秀设计实屏对标；采用项目已确认规范和用户批准的方法。后续正式方案仍需补齐参考实屏。

## 1. 整体设计契约

### 页面任务与信息顺序

| 页面家族 | 页面首先帮助用户完成什么 | 固定阅读顺序 | 允许的布局差异 |
|---|---|---|---|
| 浏览与选择 | 判断作品／服务方是否适合，再建立联系 | 人或作品身份 → 内容与能力 → 服务与价格 → 预约 | 作品允许图像主导，列表允许双列，服务详情允许连续条目；不把交易表单也改成作品瀑布流 |
| 编辑与管理 | 完成一组资料或处理一项待办 | 当前任务 → 当前资料／待办 → 缺项与反馈 → 保存／下一步 | 工作台有界预览，完整列表承接数量；表单按任务分组；编辑只显示当前上下文的工具 |
| 合作与交易 | 明白当前阶段、由谁操作以及结果 | 当前阶段与责任方 → 已确认事实 → 本阶段操作 → 历史与说明 | 金额和重要条件优先；无操作时显示等待理由；不强行添加主按钮 |

共享同一字体、间距刻度、控件及状态语义，允许业务决定结构。相同点击能力不意味着相同视觉：整行导航、标签、选择项、关注、喜欢和提交必须有各自的制式。

### 基础规则的实施解释

1. **字体**：仍以 README 的六级文字为唯一目标。页面标题最多一个主层级；导航已明确任务时，不在内容区重复同名大标题。正文400、标签500、标题600；800字重不再作为常规强调。状态、金额、说明不同时加粗。大金额属于需登记的专用展示变体，不能扩散到普通正文。
2. **空间**：32rpx页边距；模块内部用8／16／24rpx；模块之间32／48rpx按语义分组。不是把所有gap替换成同一个值。父容器负责组间距，组件负责内部；底部安全距离单独计算。
3. **按钮**：主操作使用珊瑚实色；次操作中性低强调；导航行为优先行＋箭头；危险动作以语义区分。取消、复制、筛选、关注不能套主按钮。取消通用次按钮的彩虹边框与投影，品牌装饰保留在明确品牌场景。
4. **表面**：暖白底、白色必要容器、细分隔；连续事实和订单使用列表。禁止“卡片套卡片套卡片”表达本可由文字和分隔线说明的关系。普通信息不同时使用彩色底、描边、阴影和徽章。
5. **身份**：同一实体的公开身份统一圆形头像与昵称；列表紧凑版、详情标准版、编辑大版允许尺寸变化但共用遮罩、缺省图与实体来源。角色标签独立于头像，不把未验证身份装饰成认证。
6. **品牌**：保留用户提供的珊瑚吉祥物、职业入口和现有品牌资产。大图适用于登录、明确成功反馈；订单处理不重复插入品牌大图。图标语义固定，不以彩虹替代选中／错误／锁定的含义。
7. **反馈**：业务条件未齐时可定位缺项；请求中固定尺寸且阻止重复；读取失败不显示为零；空列表不伪造计数。暂不可用能力显示真实原因和已有下一步。

以上是下一轮实施的共同契约，不宣称现有页面已经消费这些规则。订单状态、账号隔离、支付边界、真实日期规则不得为好看而改写。

## 2. 19类模块逐项审查

全部关联页面以 [INVENTORY.md](INVENTORY.md) 的反向清单为准。以下“示例”是定位证据，不是缩小实施范围。每个模块落地前运行影响查询，覆盖直接依赖和仍然复制实现的页面。

| 模块 | 观察与判断 | 统一设计决定 | 通过条件与仍缺证据 |
|---|---|---|---|
| navigation 导航 | 上下导航已有共用组件；订单两身份、兼容入口画面可比较。橱窗编辑在导航与正文重复标题；固定区规则仍散落多页 | 保留角色与返回体系；正文标题表达具体任务；安全距离由页面壳与实际栏高统一负责 | 根页、详情、弹层、无Tab页均无重复标题和遮挡；补320／414宽度及真机安全区 |
| identity 身份 | 作品详情圆头像、我的及编辑页圆角方头像、评价页又是另一种形状；名字字重与职业混排不同 | 建立紧凑／标准／编辑三种明确尺寸变体，统一圆形遮罩、长名省略和角色标注 | 同一账号跨页头像昵称一致，长昵称不挤掉关注；保持供需身份独立 |
| search 检索 | 发现与结果页入口结构接近，但搜索层样式各自实现；本轮结果页落在空结果态 | 共用搜索输入、清空、历史项和面板布局；职业／作品人与筛选各保留语义 | 同一条件跨入口回显；取消不提交；补有结果、历史长词、筛选展开画面 |
| work-card 作品卡 | 公开作品卡已共享；橱窗编辑卡另有结构、背景和置顶操作。不能把编辑卡简单当成公开卡复制 | 公开卡保留图片→身份→标题→标签→价格；编辑卡复用内容核心，另加管理工具区 | 窄双列、长标题、无图与真实多图；编辑预览与公开页相同内容，无工具误入公开页 |
| work-content 图集 | 已认可的连续图集和底部操作职责清楚；占位素材只能验证布局 | 保留原图比例、连续阅读、底部独立预约；代码／标签为辅助层级 | 最后图文可完整滚动到固定栏上方；补真实横竖图、长文、加载失败 |
| follow 关注 | 作者行文字关注正确；我的与资产页属于关系入口，不应强行放相同关注按钮 | 关注只对PROVIDER；文字加号／已关注，取消和请求中不改变几何尺寸 | 同作者不同作品联动、失败回滚、本人隐藏；本轮未重新完成这些交互测试 |
| like 喜欢 | 作品详情心形与作者关注分开，方向正确；资产页本轮为空态，不能据此确认有内容视觉 | WORK心形状态共用；我的入口与作品列表读取同一关系；不为“统一”把关注改心形 | 选中／取消后数量与列表一致；需补资产有内容、跨页返回与失败状态 |
| services 服务 | 详情、预约、合作条件和编辑页对同一服务的价格、说明、选中呈现不同；详情存在容器层层嵌套 | 共用服务事实；展示、选择、编辑三种变体。选中是复选语义，展开是详情语义；两者不混用 | 名称、描述、价格、地点各有固定层级；长描述、多个服务、不可覆盖城市不挤压金额 |
| calendar 档期 | 公开与编辑均使用日历，但日状态字很小；满客与锁定需要保留差异。源码存在15rpx状态字 | 日历共用尺寸和图例；展示强调可约、编辑强调修改与锁定；状态不能仅靠颜色 | 不新增日期假数据；补真实月份边界、选中、锁定、修改保存及小屏阅读 |
| form 表单 | 预约、项目、账号、回复的输入面、标题、帮助字与行距各自定义；项目资料显示城市但仍提示缺项 | 字段统一标签→输入→帮助／错误；只读值也需要明确表现；错误锚定字段 | 空／有效／错误／键盘状态一致；项目城市矛盾单列为交互问题，不能用删提示遮掩 |
| media 媒体 | 作品管理、参考资料、交付附件在大小与操作位置上差异明显；本轮只看到默认和已有附件 | 按图片与文件区分预览；统一增加、移除、上传中、失败重试工具；保留原生选择 | 顺序一致、取消无变化、失败可重试；补上传进行中、失败、多附件与真实图像 |
| order-list 订单列表 | 双身份列表已有连续行，应保留；工作台有界预览方向正确。状态、时间和订单号偏小，价格／标题偏重 | 共用完整订单行与工作台紧凑变体；固定信息顺序与状态列，保持现有全列表入口 | 双身份相同订单事实一致；长名称不挤压金额；10条以上阅读不靠巨大卡片 |
| order-facts 订单事实 | 共享样式已有但字号23／21rpx、加粗800与详情体系冲突；同事实有编号卡和普通行 | 同一事实模型＋统一事实行；编号只用于有顺序的步骤，普通事实不用假步骤编号 | 详情／验收／协议显示同值，同样字体层级；缺省不误写为零或已完成 |
| agreement 合作／NDA | 双方任务方向明确，但大标题、状态条、重复解释争抢层级；订单详情本轮落在前置阶段提示 | 当前阶段→谁操作→条件摘要→主动作；协议正文按需查看；复用签署状态行 | 待对方不出现可签假按钮；补可签、已签和双方条件差异；本轮前置提示不算详情全验收 |
| payment 付款／资金／验收 | 资金页诚实显示待开通；验收页主次按钮沿用粉色渐变和彩虹次按钮。未实测真实付款 | 金额、阶段、下一步为主；核对中与成功明确分开；交易反馈沿用统一动作与事实 | 付款中不重复提交，未开通不虚构余额；需补待付款／核对／失败／成功画面与真实渠道证据 |
| project 项目 | 项目列表连续行可保留；详情大渐变概览、嵌套事实、很长来源说明增加负担 | 概览精简为名称／日期／状态；关联订单复用行；资料分组；长说明可读展开而非直接截断丢失 | 增删关联有明确对象与返回结果；同订单不在项目内另造状态；资料编辑回显准确 |
| review 评价 | 评分展示、成功反馈和互动星形风格不同；服务方列表默认展开多个大回复框，拖长页面 | 区分只读评分、选择评分、结果反馈；评价列表先读内容，当前回复再展开编辑；保留已回复正文 | 星级有文字反馈，未评不显示零分；补未提交／提交失败／已回复及回复展开状态 |
| page-state 页面状态 | 空作品、空资产、前置提示、成功吉祥物没有共用结构。大空白需由真实空状态解释 | 列表空态轻量；错误有原位重试；成功可用品牌插图；不把所有状态做成成功卡 | 每页加载／空／失败分开；失败不清掉有效旧内容；本轮只覆盖部分默认／空／成功态 |
| actions 操作按钮 | 最严重：全局次按钮彩虹描边／阴影，页面主按钮实色／粉渐变／橙渐变并存；取消也很抢眼 | 按主／次／文字／危险／选择／社交分家；共享内部字号、热区、状态。先迁移全部消费者再移除旧覆盖 | 同语义跨页一套实现；普通button不自动变主动作；长文案与请求中不跳尺寸；生产能力边界不变 |

| 优先级 | 问题与证据 | 处置方式 |
|---|---|---|

## 5. 防止重复问题的审查单

- 设计前：页面任务、主要动作、信息顺序、同实体来源、组件变体、所有消费页。
- 设计中：同模块并排比较；至少比较默认、选中、请求中、失败；差异有业务理由。
- 实施前：运行design:impact；确认唯一修改源、遗留副本、全局覆盖和样式隔离。
- 实施后：运行design:check和相关业务回归；更新登记；对影响清单逐页核验，不只检查修改文件。
- 交付时：分别列设计决定、实际迁移、当前画面、交互证据、缺口；没有截图的状态不写“美观已通过”。

此审查单补充现有README的执行解释，不新增另一套字体、间距或色值来源。
