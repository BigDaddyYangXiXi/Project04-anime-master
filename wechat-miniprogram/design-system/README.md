## 3. 三层实现，避免再次分散

1. **设计值层**：用 `var(--am-type-body)`、`var(--am-space-4)` 等语义变量。app.wxss与自定义组件已导入生成的运行时设计值；已迁移属性会联动。仍存局部字面量，不得声称所有属性都已迁移。
2. **模块层**：同一内容结构和交互反复出现时，复用组件；纯视觉规则用共享样式；订单阶段、金额等业务含义复用业务模型。只共享实际相同的部分，不制造万能卡片或万能表单。
3. **页面层**：只编排模块、绑定实体与角色、控制业务条件。页面可决定模块顺序与布局，但不复制组件内部按钮／字号／图标状态。

同一个数据服务不等于同一种控件：PROVIDER 关注与 WORK 喜欢使用同一服务，但操作对象、文案和图形不同，应分别定义模块。反过来，同一种“主操作按钮”即使出现在不同业务页面，也必须共用视觉与请求中状态规则。

### CSS 约束

- 禁止新增全局 `page .content-card` 这类宽泛强制覆盖；禁止通过叠加 `!important` 修正一个页面。
- 共享样式使用模块前缀；页面容器只管理布局。原生 button 的宽度、对齐和文字继承须由按钮模块显式定义。
- 原生 picker、input、textarea 保留原生能力；统一外层字段标题、输入面、帮助与错误提示，不改成假控件。
- WXSS 变量跨自定义组件的继承必须在开发者工具验证；组件隔离导致变量不可达时，通过明确的组件属性／样式属性绑定，不能再复制字面值。
- 例外必须说明：业务理由、局部作用域、受影响页面、样例截图、退出／收敛条件。不能用“页面特殊”当理由。

## 4. 基础视觉与空间规则

设计尺寸仍为 375px；常规 rpx = 设计 px × 2。安全区域和最低触控热区使用实际布局值，不能只按缩放后的外观推测。

当前字号、行高、字重、颜色和圆角统一读取 [自动生成的设计值参考表](TOKEN-REFERENCE.md)。金额角色与检索文字例外见当前专项契约，不再维护与 tokens.json 分离的数值表。

- 正常字号只从设计值参考表中的等级选择；同模块不能因页面不同改字重。固定像素旧规格按批准的迁移映射处理，不能机械取最近数值。
- 数字金额采用等宽数字特性；不使用假空格对齐价格。文本换行、长昵称和价格位数变化不能挤掉操作。
- 间距刻度为 8／16／24／32／48／64rpx，对应细间隔、图文间隔、组内、页边距、区域间、重点区域。密集表格和边框可以有有依据的细尺寸例外。
- 区分三种间距：模块内部由模块负责；模块之间由页面编排负责；固定层与滚动内容之间由页面壳负责。不能对同一空间重复添加 margin 与 padding。
- 控件圆角 20rpx、普通卡片 24rpx、标签 8rpx、胶囊 999rpx。不是所有内容都需要卡片；连续列表优先用行与细分隔。
- 暖中性深色为内容底，浅色为正文，Logo 桃橙为主动作／选中态。彩虹用于品牌细节，不改变常用图标语义。不把渐变、阴影和模糊作为通用装饰。
- 点击区域至少 44px；图标可以小于热区。需要扩大热区时不能把可见图标同时放大成装饰。
- 固定底栏高度来自同一来源或实际测量；正文余量=业务栏高度＋主导航高度＋安全区＋必要间隔。禁止每页各猜一个 bottom 数值。

### 按钮状态矩阵（所有模块共用）

2026-09-24 普通读取状态按用户最新要求保持安静：不展示“正在读取／正在加载／请稍候”等过程句，也不因后台刷新插入提示块或清空已显示的同账号资料。首次未知数据不得伪装为真实结果；真实错误和重试保留。账号展示复用当前已验证会话，缓存按账号隔离并在退出时清除；保存后的昵称及时更新。已保存城市可先回显后核对，未设置城市仍由用户选择，不推定为GPS定位。2026-10-06：需求方发现页默认不限日期，使用本人职业排序的第一项；主动选择日期后在返回时保留。首次使用解释大致位置用途，只有主动点击允许后才调用微信隐私授权与模糊定位；拒绝时保留手动选城市。头像昵称沿用主动填写，不能把旧版公开资料授权描述成当前自动取得的能力。付款核对、提交与保存的业务状态不属于普通读取提示。

| 状态 | 视觉 | 行为 |
|---|---|---|
| 可执行 | 主按钮品牌橙色；次按钮低强调；文字动作无大边框 | 一次点击产生一个明确结果 |
| 业务条件未齐 | 保持可理解的动作与条件提示，不仅降低透明度 | 点击定位缺项／展示缺项；不能无解释失效 |
| 请求中 | 固定尺寸，显示进行中，阻止重复请求 | 成功后更新实体；失败恢复可操作 |
| 当前不适用／权限禁止 | 隐藏或明确原因；需要发现性的功能保留原因入口 | 不绕过业务权限 |
| 已完成／已选中 | 图形与文字同时变化，颜色作为补充 | 可撤销动作可恢复；不可重复的操作不重发 |
| 错误 | 解释失败并提供重试；输入和此前有效状态保留 | 不能把失败渲染成空记录或已完成 |

不要求不同业务的所有按钮文案相同；要求同一语义的结构、状态和反馈一致。批量文字替换不能替代模块化。

## 6. 修改与联动流程

1. 明确变更对象：设计值、共用模块，还是页面编排。先写用户任务、主要动作、入口／出口、数据实体和不变项。
2. 查询影响范围：`npm run design:impact -- like`，或传入 `miniprogram/components/work-card/index.wxss` 等真实路径。
3. 结果包含两部分：**直接依赖页**会随共享代码变化；**语义相关页**可能仍各写一份，必须一并检查。任何未识别文件不能按“零影响”放行。
4. 修改唯一来源。若发现本地副本，先迁移至共用实现，再删除本次产生的重复样式；不要同时保留两套活跃实现。
5. 登记受影响页的角色／界面分支／状态矩阵；新交互入口同步到该页目录。重新生成页面清单。
6. 运行静态检查与对应业务测试；对影响清单逐页检查运行画面。缺乏环境证据的页面明确保留未验证状态。
7. 修改记录列出“已联动、已验证、尚未迁移／验证”。不能只报告 A 页截图而省略 B 页。

### 例：修改喜欢作品

影响范围至少有作品详情、个人中心、我的内容资产；分别验证按钮状态、资产入口／数量来源、列表新增／移除与空状态。状态写入仍是 WORK；关注 PROVIDER 不受影响。数据需要更新时，前端显示、服务请求和持久层必须对应；纯样式变更不应借机改数据结构。

### 新模块扩展

先选择是否可复用现有模块，再登记新 ID、用途、数据源、允许变体、页面消费者、状态和例外。只有一个消费页时可以保持局部实现，但必须进入目录且使用共用设计值；出现第二个相同模块时评估抽取，不能直接复制。

## 7. 自动检查能保证什么

- 路由不能漏登记，模块 ID 不能悬空，共享来源文件必须存在。
- 页面新增／移除绑定交互后，该页目录必须同步复核；不能只修改另一页的目录绕过检查。
- 扫描范围内的新局部字号、间距、颜色、圆角等声明会报错；允许删除旧债务，不提供整体刷新基线的逃生口。
