# 信息缓存规则

2026-10-20用户要求：在双身份预加载基础上缓存高频展示、低频修改的信息，同时遵守小程序容量限制。本规则与[预加载规则](PRELOAD-POLICY.md)共同生效。预加载决定何时读取，缓存决定能否复用；预加载必须使用同一服务缓存，不另造页面副本。

## 适用信息与时效

| 信息 | 当前缓存方式／有效期 | 更新规则 |
|---|---|---|
| 本人昵称、头像链接、基本资料 | 当前账号内存15分钟 | 保存后更新/失效；头像变更重解链接；不凭本地副本认定登录 |
| 已确认城市、职业顺序和授权选择 | 内存复用；偏好按原账号隔离持久化 | 城市读取缓存15分钟，真实会话/新保存结果覆盖旧值；授权变化按微信当前结果；持久偏好不是无限期业务事实 |
| 本人喜欢/关注关系 | 内存15分钟 | 增删前后失效，迟到结果不得复活旧缓存 |
| 本人公开橱窗文字、稳定编辑草稿 | 内存最多15分钟 | 保存/发布/退出失效；只有媒体状态满足原安全条件的完整编辑草稿可复用，不把审核中状态固化 |
| 预加载原始草稿文字及资源编号 | 内存30秒、与前台合并 | 保存/发布前后失效；不缓存媒体状态或据此判定审核通过 |
| 项目列表及用户主动打开的项目文字 | 内存5分钟 | 创建/修改/关联订单后失效；预加载不主动展开项目正文 |
| 公开目录原始读取 | 内存1分钟；发现页有效首屏按现有5分钟返回规则复用 | 按账号、职业、城市、日期、筛选和分页参数隔离；发布变化失效，不能跨查询混用 |
| 首页首屏、个人页等展示快照 | 本地5分钟，最多6份，当前已验证账号可读 | 只用于先显示，页面继续按原逻辑更新；不作为接单/支付/退款/权限决策依据 |
| 订单列表、档期、收到互动、资格和反馈展示读取 | 仅原有30秒短缓存 | 高频变化，不延长为15分钟；执行动作仍实时校验；详情不因列表预热而提前读取 |
| 图片临时链接 | 沿用现有账号/文件隔离的15分钟内存缓存、最多128项 | 到期、图片变化、退出失效；不承诺链接撤销由客户端缓存自动保证 |
| 订单执行详情、支付退款、银行税务、审核媒体状态 | 不新增缓存 | 保持实时调用和鉴权；不缓存失败结果，不以旧成功替代未知结果 |
| 图片/视频二进制、私人附件 | 不写Storage缓存 | 不新增下载或Base64持久化；现有原生图片缓存交由宿主管理 |
| 未提交编辑、待恢复退款/反馈请求及幂等编号 | 属于用户工作状态，不是可淘汰展示缓存 | 不因空间不足清除；按各业务完成/取消/恢复规则处理 |

以上大部分TTL沿用已有实现，不通过统一拉长有效期制造速度提升。权限、资格、库存/档期、审核及资金事实均不能由缓存决定；待审核作品仍只在本人编辑流程可见，不能因缓存而公开。

发布变更对照按需实时读取，不增加缓存；稳定编辑草稿仅当所有关联媒体（含头图原图、取景图、须知图、案例原图）均为 READY 且没有待处理发布任务时复用。

## 容量与小程序约束

微信开发者文档入口本轮无法直接读取；核对到腾讯官方小程序API文档所述单key 1MB、总Storage 10MB，以及`getStorageInfoSync`的`currentSize/limitSize`单位KB。该来源属于腾讯云超级应用服务文档，不能冒称已核实所有微信版本的最新行为；实际运行以微信返回的`limitSize`和写入结果为准。

- [微信setStorage文档入口](https://developers.weixin.qq.com/miniprogram/dev/api/storage/wx.setStorage.html)
- [腾讯官方数据缓存API及容量说明](https://www.tencentcloud.com/document/product/1219/57698)

本项目使用更低的自定预算，不能把平台上限全部占满：

| 层 | 已落实的上限 | 淘汰／降级 |
|---|---|---|
| 共用原始请求内存缓存`read-cache` | 最多80项，单项含请求key不超过256KiB，总JSON负载2MiB | 到期/时钟回退清除；命中更新使用顺序；总量超限淘汰最久未用项；大响应照常返回但不保留 |
| 本地展示快照`display-cache` | 单快照128KiB，6份以内，整个Storage key JSON不超过512KiB | 新快照优先，超总量去掉旧快照；过期/其他账号记录不续存 |
| Storage余量 | 每次写快照前读取实际配额，保守要求“当前用量＋本次完整写入量”仍留下1MiB | 配额不明、读取失败、空间不足均跳过可选写入；真实读取/保存结果不因缓存失败变成失败 |

字节按UTF-8 JSON计算，中文不是一个字符一个字节；包含JSON结构。内存2MiB是该请求缓存的序列化负载预算，不是整个小程序JS堆或全部服务副本的总内存承诺。已发请求、页面状态、服务层单账号缓存和图片解码仍占内存，真机需单独测量。

不调用`clearStorage`清空全库、不删除未提交草稿或请求编号、不为缓存另建文件下载目录。偏好小记录及业务恢复记录仍由各模块管理；本次未将所有Storage键迁移到统一配额管理器，也不声称业务记录永远不会写满。各业务仍须保留存储失败处理。

## 一致性与身份边界

- 双身份共用本人资料；页面展示快照仍按身份/查询区分，避免需求方统计显示成服务方统计。
- 必须有服务器确认的账号才能读取缓存；退出或切号清理/隔离，旧请求不得写入新账号。
- 写操作开始和结束均失效相关读取缓存；发布/资料更新清除展示快照。缓存命中不绕过服务端版本冲突、审核或交易校验。
- 首屏不新增全量同步Storage扫描或预写；复用已有读写入口，原生写入异常兜底。
- 缓存key/数据结构改变必须版本化或清理对应可选key，禁止以清空账号登录和用户草稿完成迁移。

## 实现与验收

本轮只增强`utils/read-cache.js`、`utils/display-cache.js`及共用UTF-8计量`utils/cache-size.js`；不改变已批准UI、业务规则或各信息TTL。

本地94项相关回归通过，包括中文/emoji字节计量、单项/总量限制、LRU、空间不足保留未完成请求、缓存失败容错、写后失效、账号隔离及双身份预加载。唯一客户端同步后再编译生效；未上传或部署。真实设备Storage用量、内存峰值和启动耗时未验收。

## 2026-10-20 上传恢复记录

`animeMasterPendingAvatarV1` 和 `animeMasterPublicationIntentV1` 各只保留当前账号一个小型任务记录，24小时有效，不存图片字节／昵称正文。退出清除、按账号核对、写失败兜底；属于用户未完成工作，不能加入通用展示缓存的LRU清理。服务端已确认任务可在本地记录丢失后按账号／草稿版本回查。
