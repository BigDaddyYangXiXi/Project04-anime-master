# 界面测试场景台

入口：[打开测试场景台](http://127.0.0.1:9433)。这是本机工具；关闭电脑后需重新启动。启动脚本：`automation/start-state-lab.ps1`，微信开发者工具自动化端口需为9422。

## 怎么使用

1. 选择需求方或服务方，搜索页面名、状态或场景编号。
2. 点击场景，在微信开发者工具中滚动、点击、返回并继续操作。
3. 如需在场景台看画面，选中“同时截图”，再点击场景；截图会增加等待时间。
4. 发现问题时记录场景编号、操作步骤和截图，例如“S028：付款待核对，底部提示被挡住”。
5. 再次点击场景会重置整组订单、项目和关注／喜欢数据，因此不会继承上一轮对这些实体的修改。橱窗编辑等其他原有本地草稿不会被清除。
6. “恢复测试前数据”恢复首次加载前备份的订单、项目、关注／喜欢、身份和预览开关。

## 本次数据

生成器：`automation/state-fixtures.js`；完整数据和入口参数：`.artifacts/state-lab/fixtures.json`。订单使用独立UI编号，包含状态机的全部12个订单阶段、付款失败／确认中／待核对、NDA双方签署、现场服务／文件交付、未评价／已评价／已回复。订单的身份、职业、服务、金额、时间与项目关联使用同一数据源。

26个登记页面都有入口。额外场景覆盖登录注册、搜索筛选、预约时段与冲突、供需订单分类及空列表、档期修改、作品和服务编辑、图片审核提示、关系状态、收款资料和资金记录，以及模板中存在的读取中与读取失败分支。

标记为“界面状态注入”的场景用于查看瞬时界面，不代表真实网络请求或真实上传；重新选择“完整内容”场景会恢复正常本地分支；这些注入场景不用于验收真实重试请求。资金资料与记录是调用原页面渲染方法的模拟响应。生产端尚未实现的结算／退款等状态不编造成功页面。

## 验证边界与已知问题

- `.artifacts/state-lab/checks.jsonl`记录逐次打开检查；同一编号有重试时以最后一条为准。打开检查包括实际页面数据和实体对应，不等于所有像素、所有交互或真机验收。
- 所有fixture和控制服务均在小程序上传包外；控制服务只绑定本机地址，并校验访问来源与随机请求标记。只有开发工具模拟器可载入，原云端隔离检查继续适用。
- 测试数据没有有效支付参数，不会完成真实微信付款；文件交付列表用于检查界面，旧本地附件没有云文件ID，不能据此验收真实下载与预览。
- 部分原有本地档期页面仍固定2026年8月，与新订单日期不一致；这是已暴露的旧预览逻辑问题，未通过生成旧日期订单掩盖。
- 内置浏览器自动检查连接遇到插件文件缺失，未把场景台浏览器交互标为已验收。HTTP入口与微信开发工具数据检查分别记录。

本轮不修改业务后端、数据库、支付规则或发布配置。
